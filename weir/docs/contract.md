# The reject-vs-degrade contract

Exit-2 rejects are exactly two conditions: the input is not JSON at all (neither a JSON document nor JSON Lines), or the input is JSON but not OTLP-shaped (no `resourceSpans` list found anywhere). Everything else degrades, named by one of the rows below.

| reason | trigger | what weir does | remediation |
| --- | --- | --- | --- |
| invalid_encoding | input bytes are not valid UTF-8 | decoding continues with U+FFFD in place of the invalid bytes; no node is marked degraded, but content-derived joins and taint can be silently wrong | the input is not valid UTF-8; invalid bytes were replaced with U+FFFD, which can silently alter content-mined join evidence and taint payloads - fix the exporter's encoding |
| undecodable_batch | a JSONL line failed to parse as JSON | the line is skipped; decoding continues with the remaining lines | one or more JSONL lines could not be decoded; re-export the batch or check the exporter's file rotation for mid-write truncation |
| non_trace_batches_skipped | a batch decoded fine but carries no resourceSpans list | the batch is skipped entirely; its spans never enter the trace | lines that decoded but carry no resourceSpans list (logs/metrics in a mixed export, or a malformed traces batch) were skipped; export traces to their own well-formed file |
| undecodable_span | a span object failed structural decode against the wire schema | the span is discarded; it never becomes a node - absent from the trace | a span failed structural decode and was quarantined; check the exporter for schema-violating span serialization |
| undecodable_scope | an instrumentation scope object failed structural decode | the scope is replaced with an empty scope; its spans are still mapped but lose framework identity | an instrumentation scope failed structural decode and was dropped; framework identity for its spans is lost - check the exporter's scope serialization |
| orphaned_parent | a span's parentSpanId names no span present in this export | the parent link is cleared; the node is kept but appears unlinked, not marked degraded by this alone | a span references a parent absent from this export; include the full trace in one export (or concatenate the batches into one JSONL file) |
| duplicate_span_id | two or more spans carry the same span id | byte-identical duplicates collapse to one node; differing duplicates keep a digest-suffixed id and any join touching them is dropped | two spans share a span id; check the instrumentation's id generator or de-duplicate the export |
| missing_span_id | a span's spanId is empty | a digest-derived surrogate id is assigned so the node can still be created and joined | a span carries no id; upgrade the exporter - joins to this span cannot be trusted |
| nonstandard_id_encoding | a span id is not OTLP/JSON lowercase hex | processing continues unaffected; linkage still matches on the raw token | span ids are not OTLP/JSON lowercase hex (base64 protojson output is the usual cause); linkage is unaffected, but spec-true hex ids are recommended |
| unmappable_genai_span | gen_ai.operation.name is absent and no gen_ai.tool.name marker is present either | the span is dropped; it never becomes a node - absent from the trace | a GenAI span's operation could not be derived; set gen_ai.operation.name on every GenAI span |
| non_genai_spans_filtered | a span carries no gen_ai.* attribute | the span is filtered before mapping and never becomes a node - expected, not a defect | non-GenAI spans (http/db/plumbing) were filtered from analysis; this is normal and not a defect |
| missing_content | the content attribute for this node's kind is absent | the node is created with empty payload content and marked degraded -> excluded from verdict-eligible coverage | content capture is off; for OTel GenAI instrumentations built on the util-genai layer, set OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental and OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=SPAN_ONLY to capture gen_ai.input.messages / gen_ai.output.messages / gen_ai.tool.call.arguments and unlock cross-step analysis |
| unparseable_content | a content attribute is present but its JSON does not parse, and the failure does not fingerprint as truncation | the node is created with empty payload content and marked degraded -> excluded from verdict-eligible coverage | a content attribute was present but not parseable; check the instrumentation's payload serialization |
| truncated_content | a content attribute's JSON cuts off at end-of-input or inside an unterminated string | the node is created with the truncated payload and marked degraded -> excluded from verdict-eligible coverage | a content attribute appears truncated (payload limit hit); raise the exporter's attribute length limit |
| invalid_timestamp | startTimeUnixNano is missing, non-numeric, or negative | the node gets a synthetic epoch timestamp, ordering falls back to span id, and it is marked degraded -> excluded from verdict-eligible coverage | a span timestamp was unparseable; ordering fell back to span id - fix the exporter's clock fields |
| ambiguous_join | join evidence (explicit id, nesting, or a mined id) matches more than one candidate, or a duplicated id is shared | no join is recorded for the affected call; without an eligible join confidence it is excluded from verdict-eligible coverage | join evidence matched multiple candidate spans, so no join was recorded; ensure tool call ids are unique per trace |
| conflicting_join_evidence | an envelope join (explicit or nested) already exists for a call, and mined content evidence points to a different result | the envelope join is kept per precedence; the disagreement is only recorded, coverage for that call is unaffected | two join sources disagreed and precedence resolved it; this is the fingerprint of malformed instrumentation or attempted linkage forgery - inspect the named spans |
| unknown_dialect | no schemaUrl or attribute fingerprint matches a registered dialect | mapping proceeds under the default profile but every resulting node is marked degraded -> excluded from verdict-eligible coverage | the trace matched no registered dialect; it was mapped under the default profile with every node degraded - tell us which instrumentation produced it |
