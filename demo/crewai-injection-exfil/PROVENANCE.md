# Provenance of the committed captures

`capture-injected.jsonl` and `capture-benign.jsonl` are **representative**, not a
recording of a live agent run. They are generated by
`make_representative_capture.py`, which is committed alongside them so the
synthesis is fully auditable - nothing here is a black box.

## What "representative" means and why it is honest

The captures are hand-built to the **exact span shape OpenLIT's CrewAI
instrumentation emits**, verified against primary source
(`openlit/openlit`, `sdk/python/src/openlit/instrumentation/crewai/utils.py`):

- a tool call is ONE span, kind INTERNAL (1), named `execute_tool <name>`;
- attributes `gen_ai.operation.name="execute_tool"`, `gen_ai.tool.name`,
  `gen_ai.tool.type`, `gen_ai.tool.description`, `gen_ai.tool.call.arguments`,
  `gen_ai.tool.call.result`;
- **no** `gen_ai.tool.call.id` (OpenLIT does not set it);
- content captured by default (`capture_message_content=True`).

The OTLP/JSON envelope (camelCase keys, hex span ids, string nanos, one batch
per JSONL line) mirrors the real collector-exported capture committed at
`fixtures/foreign/langchain-collector/capture.jsonl`, which came from a real
`otelcol-contrib` file exporter.

What is therefore NOT third-party here: the bytes were produced by this repo's
generator, and the model's decision to forward the IBAN is scripted rather than
elicited from a live LLM. `agent.py` + `collector.yaml` are the harness to
produce a genuinely third-party capture (real CrewAI, real OpenLIT, real
collector) whenever you want to upgrade this demo from representative to
recorded - the same path this repo's langchain foreign-capture took.

## The planted value

`DE89370400440532013000` is the well-known German test IBAN, valid under
ISO 13616 mod-97, which is what clears weir's `financial_account_identifier`
eligibility. It is not anyone's secret.
